# 5. Commentary and summaries with verified numbers

**Question:** Can a model draft commentary whose numbers are verified?

## Rationale

Every release comes with text: the headline paragraph, the commentary
by topic, the note that explains a break, the summary for the press. The
numbers in the text come from the output tables, and a model given the
tables drafts the text in minutes, in the organization's style, in each
language. The risk is specific: a number in the draft that the tables do
not contain, a "lowest since" that nobody checked, a provisional value
stated as final. Each of these is checkable by machine before an
analyst reads the draft, which is what makes drafting safe: the model
drafts, the check verifies every number against the tables and lists
every claim that needs a source, and the analyst edits and approves.

## Target state

- Commentary is drafted from the release's output tables with a style guide and the series' metadata, in each publication language.
- Every number in a draft is verified against the tables before an analyst sees it; unverified numbers and unsourced claims are listed.
- The analyst edits and approves; the approval is recorded; and the published text carries no number the tables do not support.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Draft the headline paragraph from the tables; verify the numbers by hand against the tables. |
| **AI-ready** | Draft the full commentary with the style guide and metadata; run the number and claim check; record the analyst's approval; measure the edit distance per release. |
| **AI-native** | Draft in every publication language with the glossary; source comparative claims automatically from the series history; track acceptance per section and language. |

:::info[Running example]
A draft commentary for the labour force release names seven figures.
Six are verified against the release table, including a change computed
from two values and a figure stated in millions; one (jobs added in
services) is in no table and is flagged; the claim "lowest level since
2019" needs a source; the draft states that the figures are provisional.
:::

## Recipes

<Recipe title="5.1 Draft from the output tables with the style guide" level="Foundational" skills="Analyst; access to a model" time="Minutes per release">

**Result:** a draft commentary grounded in the release's tables, in the
organization's style, marked as a draft.

1. Give the model the output tables (as CSV or a compact text table with
   series, period, value, previous value, unit, status), the series'
   metadata (definitions, breaks, caveats), the style guide (length,
   order, how changes are stated, how provisional values are described),
   and last release's commentary as the model of tone.
2. Ask for the draft with the rule to use only numbers from the tables,
   to state the status of provisional values, and to mark any
   comparison beyond the tables ("highest since") as needing a source.
3. Save the draft with the model and date; it goes to the check of
   recipe 5.2 before any person edits it.

**What this does not do.** A draft from the tables says what the tables
say. The analysis (why the rate moved, what it means) is the analyst's,
and the draft is a starting text, never the published one.

</Recipe>

<Recipe title="5.2 Verify every number and list every claim" level="AI-ready" skills="Python" time="Seconds per draft">

**Result:** every number in the draft matched to a table value, a
previous value, a change, or a rounded form, with the unverified ones
and the comparative claims listed, and the provisional status checked.

```python file=../../website/static/cookbook-files/language-models-in-production/commentary_check.py
```

```bash
python commentary_check.py release_table.csv commentary_draft.md
```

Output for the running example:

```text
verified        7.4  LF_UNEMP_PCT value
verified        7.6  LF_UNEMP_PCT previous
verified       16.8  LF_UNEMP_PCT_YOUTH value
verified       61.2  LF_PART_RATE value
verified       4.31  LF_EMPLOYED value in millions
verified     44,000  LF_EMPLOYED change in units
UNVERIFIED   38,000  not in the release table
CLAIM      lowest level since 2019.

6 verified, 1 unverified, 1 claim(s) needing a source; provisional values are stated as provisional
```

1. Run the check on every draft; a draft with an unverified number or an
   unsourced claim cannot leave the pipeline.
2. For an unverified number, either add the table it came from to the
   inputs (the figure for services came from a table the draft was not
   given) or remove the sentence.
3. For a claim, source it from the series history (the dissemination
   cookbook's [number check](/cookbook/ai-ready-dissemination/trust)
   and the [series files](/cookbook/ai-ready-dissemination/retrieve)
   hold it) or remove it.
4. Keep the check's output with the draft as the verification record.

**What this does not do.** A verified number can be attached to the
wrong series in a sentence; the analyst reads the draft. The check
covers numbers and the claim patterns it knows; a new pattern is added
when an analyst finds one.

</Recipe>

<Recipe title="5.3 Edit, approve, and measure" level="AI-ready" skills="Analyst; head of the unit" time="Part of each release">

**Result:** published commentary approved by an analyst, with the
approval recorded and the edit distance per release tracked.

1. The analyst edits the checked draft in the publication tool and
   approves it; the approval, the analyst, and the date are recorded
   with the release.
2. Re-run the check on the final text; an edit can introduce a number.
3. Measure the edit distance between the draft and the published text
   per section; a section always rewritten is a prompt or a style guide
   problem, and a section never edited is one to read with more care,
   because unread text is unreviewed text.
4. For other languages, draft with the glossary and run the translation
   checks of the [curation cookbook](/cookbook/metadata-curation-with-llms/translate);
   a native speaker approves each language.

**What this does not do.** Approval makes the text official; it does
not make it right beyond the analyst's knowledge. The check and the
review together are the control, and the statement of model use
([chapter 7](./assurance.mdx)) says they were applied.

</Recipe>

## Implementation options

- **Inputs:** output tables, series metadata, style guide, previous commentary; a glossary per language.
- **Check:** the script in this chapter for numbers, changes, rounding, claims, and status; the dissemination cookbook's number check against the full series for claims.
- **Approval:** recorded in the publication tool; the check re-run on the final text; edit distance per section tracked.
- **Languages:** draft per language with the glossary; translation checks; native-speaker approval.

## Common mistakes

- **Drafts edited before the check.** The check runs first and last.
- **Tables the draft was not given.** A number from memory is the error the check exists for.
- **Claims left in.** "Lowest since" is a number nobody computed.
- **Unedited sections.** They were not read.

## Verification

- **Check:** every published commentary has a check record with zero unverified numbers and every claim sourced.
- **Approval:** recorded with analyst and date; the final text re-checked.
- **Measure:** edit distance per section tracked per release.
