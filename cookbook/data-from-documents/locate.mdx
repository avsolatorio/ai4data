# 3. Location of tables and figures

**Question:** Can the tables and figures be located on the page?

## Rationale

Before a table can be extracted, something has to find it: the page, the
region on the page, and whether it is a table, a chart, or a map. Layout
detection models do this from the page image and return a class and a
bounding box for each region. The region cropped from the page is a **data
snapshot**: a self-contained image of one table or figure, with its
coordinates, which the extraction in [chapter 4](./extract.mdx) reads and
which every later citation points back to.

The program's Data Snapshots work benchmarked open-source layout detection
models on institutional documents (humanitarian reports, World Bank policy
research working papers, project documents) and found that models which
perform well on academic benchmarks struggle on operational documents:
they confuse analytical and decorative content and cut off context such as
titles and notes. Detection therefore needs review, and the organization's
own documents are the right test set.

## Target state

- Every document in the inventory has been processed by a layout detection model that returns page, class, and bounding box per region.
- Each region is saved as a snapshot image with a sidecar record (document, page, bounding box, class, model, date).
- Detection quality is measured on a sample of annotated pages from the organization's own documents, and the sample grows with each review.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Locate tables from the text layer (table titles and numbered captions) and figures by hand from the list of figures. Record page numbers in the inventory. |
| **AI-ready** | Run a layout detection model over the pages, save snapshots with their coordinates, and review a sample of detections against the page. Record precision and recall. |
| **AI-native** | Run detection on every new document in the publication workflow, keep an annotated set of the organization's pages, and fine-tune or select the model on it. |

`[0.266, 0.525, 0.734, 0.781]`. The home page of the program shows the

## Recipes

<Recipe title="3.1 Run a layout detection model over the pages" level="AI-ready" skills="Developer with Python and a machine with a GPU or patience" time="One to two days to set up; seconds per page after">

**Result:** for every page, a list of the regions a model detected as a
table or a figure, each with its class and the rectangle that encloses
it.

A layout detection model looks at the image of a page and returns
rectangles (bounding boxes) around the things it recognizes: tables,
figures, text blocks. The box is written as four numbers between 0 and
1, the left, top, right, and bottom edges as fractions of the page
width and height, with the origin at the top left. The example record
below shows the fields; its box, `[0.266, 0.525, 0.734, 0.781]`, is a
figure in the lower middle of page 12:

```json file=../../website/static/cookbook-files/data-from-documents/example_snapshot.json
```

1. Render each page to an image. PyMuPDF renders pages, and 150 dots
   per inch is enough for detection.
2. Run an open-source layout detection model on the images. The
   [Data Snapshots benchmark](https://arxiv.org/abs/2606.06242) compares
   models on institutional documents; choose from its results for the
   organization's document types, and expect to review the output.
3. Store each detection as a record with the document identifier, the
   page, the class (Figure or Table), the box, the model name and
   version, and the date.
4. Keep the detections with the document, versioned, so that a later
   model run can be compared with them.

**What this does not do.** Detection finds regions; it does not read
them. It also misses context: a title above a table or a note below it
may fall outside the box, which is one of the failure modes the
benchmark reports. Recipe 3.3 reviews for this before extraction.

</Recipe>

<Recipe title="3.2 Save snapshots with their coordinates" level="AI-ready" skills="Developer" time="Part of the detection run">

**Result:** one image file per detected table or figure, named so that
it can be traced to the document and page, with its coordinates in a
small file beside it.

1. Crop each detected region from the page image, with a small margin
   so that titles and notes at the edge are kept, and save it as an
   image.
2. Name the file from the document identifier, page, and an index
   (`EX-REP-2025-03_p024_t01.png`), and write a sidecar JSON file with
   the fields of recipe 3.1 beside it.
3. When the title or the note of a table sits outside the detected box,
   extend the box to include them and record both boxes (detected and
   adjusted) in the sidecar. The adjusted box is the one later citations
   use.
4. Store the snapshots next to the document and the text layer, under
   the same version.

**What this does not do.** A snapshot is an image. Its content becomes
data in [chapter 4](./extract.mdx); until then the snapshot is what a
person reviews and what a citation shows.

</Recipe>

<Recipe title="3.3 Review detections against annotated pages" level="AI-ready" skills="Dissemination officer; developer for the scoring" time="Half a day for a sample of 50 pages">

**Result:** a measured precision and recall for the detection on the
organization's own documents, and a growing set of pages, marked by
hand, against which future runs are measured.

1. Draw a sample of pages across document types (reports, bulletins,
   yearbook, census volume) and mark every table and figure on them by
   hand, in the same box form. The `data-snapshot` dataset (476
   annotated regions in two classes, MIT licence) shows the annotation
   format and serves as a second test set.
2. Compare the detections with the annotations. A detection matches an
   annotation when their boxes overlap enough (an intersection over
   union of 0.5 is the usual threshold) and the classes agree. Count
   matches, missed annotations, and false detections, per class and per
   document type.
3. Read the misses. The benchmark's failure modes (decorative graphics
   detected as figures, tables cut from their titles, multi-panel
   figures split or merged) are the ones to expect.
4. Keep the annotated sample, add to it with each review, and re-run
   the comparison whenever the model changes.

**What this does not do.** Fifty pages give a first measure. Precision
and recall per document type need more, and a yearbook with dense
tables is a different test from a report with charts. Annotation itself
needs a short written rule for what counts as a table or figure, so
that two annotators agree.

</Recipe>

## Implementation options

- **Page rendering:** PyMuPDF (`page.get_pixmap`) or pdf2image.
- **Layout detection models:** open-source models benchmarked in the Data Snapshots work; document-layout models trained on academic corpora need the review step on institutional documents.
- **Annotation:** the `data-snapshot` format (normalized XYXY boxes, classes Figure and Table); the [COCO](https://cocodataset.org/#format-data) format is the common interchange format for detection datasets and tools.
- **Storage:** snapshots and sidecar records versioned with the document; a simple folder convention is enough until the catalog holds them ([chapter 7](./publish.mdx)).

## Resources

- [Data Snapshots](https://arxiv.org/abs/2606.06242) and the [data-snapshot dataset](https://huggingface.co/datasets/ai4data/data-snapshot): the benchmark of layout models on institutional documents and the annotated pages to review against.
- [Docling](https://github.com/docling-project/docling): layout analysis, reading order, and table structure for PDFs, with OCR for scans; a single tool for the foundational pipeline.
- [Table Transformer](https://github.com/microsoft/table-transformer): table detection and structure recognition models (MIT) for pages where tables are the target.
- [COCO format](https://cocodataset.org/#format-data): the interchange format for detection annotations, for review and fine-tuning.
- [Label Studio](https://labelstud.io/): open-source annotation of bounding boxes on pages, for the review sample and for fine-tuning data.

## Common mistakes

- **Trusting detections from academic benchmarks.** The benchmark's result is that these models do worse on operational documents; measure on the organization's pages.
- **Boxes without the title.** A snapshot without its title is a table with no name; adjust the box or record the title separately.
- **One class for everything.** A map, a photo, and a chart are all figures to the model; the extraction in chapter 4 needs to know which.
- **Discarding the page image.** The page is the evidence; keep it with the snapshot.

## Verification

- **Coverage:** every document in the inventory has detections; the counts of tables and figures replace the hand estimates.
- **Precision and recall:** measured on the annotated sample, per class and document type, and recorded with the model version.
- **Snapshots:** a sample opened by a person shows the full table or figure with its title.
