# Practical Guide to Serving Official Statistics to AI Agents

**A cookbook for developers and dissemination teams in national statistical organizations.** Version 0.1 (working draft), October 2026.

:::note[Working draft]
This guide is a working draft from the AI for Data – Data for AI program. It
collects practical approaches and open standards. Comments and corrections
are welcome as [GitHub issues](https://github.com/worldbank/ai4data/issues),
and the [contributing](./contributing.md) page explains how to propose a
recipe.
:::

AI assistants answer questions about statistics whether or not the
organization that produces them takes part. When they cannot reach the
official figures, they answer from training data, from copies on other
sites, or from guesses. An agent interface changes that: the assistant
calls the organization's own tools, receives the official values with their
unit, release, source, and licence, and cites them. The
[Model Context Protocol](https://modelcontextprotocol.io/) (MCP) is the
open standard for this. One server serves every compatible assistant.

This guide is organized around nine questions an organization can ask
before and after exposing its statistics to agents: what an agent should
be able to do with the data, which tools to offer with which inputs and
outputs, what context the agent needs beyond the tools, how every response
carries its source, who may call the interface and under which terms, how
it is kept safe, how it is evaluated, how users and developers connect,
and how it is operated and maintained. Each chapter
answers one question with recipes, maturity levels, and a checklist.

The recipes build on the program's [MCP work](/docs/mcp/) and on two
servers in operation: the World Bank's
[Data360 MCP server](https://github.com/worldbank/data360-mcp) and the MCP
interface of [NADA](https://nada.ihsn.org/). The
[dissemination cookbook](/cookbook/ai-ready-dissemination/) covers what
has to be in place underneath: a catalog, an API, and documented meaning.
The [standards page](./standards.md) lists each standard and where it
applies.

:::tip[A thin layer over a solid API]
An MCP server is a small program that wraps the organization's existing
API and catalog in tools a model can call. The quality of what the agent
returns is the quality of the API, the metadata, and the provenance behind
it. Where those are weak, the agent interface makes the weakness visible
faster; the dissemination cookbook's chapters 1 to 5 come first.
:::

## Maturity levels

Each chapter describes three levels. An organization can sit at different
levels in different chapters, and the first level is a complete, useful
state on its own.

| Level | Meaning |
|---|---|
| **Foundational** | The organization's API and catalog are documented and public, and the scope of agent access is decided; agents reach the data through the API without a dedicated interface. |
| **AI-ready** | An MCP server with read-only tools, provenance in every response, access control, and an evaluation suite is in operation for public data. |
| **AI-native** | The server is published for clients, versioned, monitored, evaluated on every change, and its usage feeds the organization's monitoring and documentation work. |

## Running example

The example organization of the dissemination cookbook exposes its five
published series through a server with four read-only tools (search,
metadata, observations, code lists) and three resources (guidance, code
lists, release calendar). A question set of eight questions, including one
the organization cannot answer and one about a region the series does not
cover, is run through an agent, and the logged traces are scored: six
questions pass, one answer gives a wrong value, and one answers a regional
figure the series does not have. A guidance resource, a client registry
with a day's requests, and a registry listing complete the example. All
values are invented.

## Scope of the examples

The examples are small on purpose: four tools, eight questions, eight
traces, so that a reader can run them in an afternoon and see the shape of
each check. They are starting points. Each recipe ends with a **What this
does not do** note that says where the example stops and what the full
version adds. The server code itself is the
[MCP example of the dissemination cookbook](/cookbook/ai-ready-dissemination/retrieve)
and the Data360 server; the scripts here check its design and its
behaviour.
