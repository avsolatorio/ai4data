# 1. Purpose and scope of agent access

**Question:** What should an agent be able to do with the data?

## Rationale

An agent interface is a commitment: the organization's figures, served to
software that will quote them, under the organization's name. Before any
code, three decisions set the shape of everything else: which uses the
interface serves (finding a series, reading its definition, fetching
values, comparing periods), which data are in scope (public data only, and
which products), and what counts as success (the right series, the right
value, the right caveat, a citation, and a refusal when the data do not
exist). A question set written at this stage represents those decisions
and becomes the evaluation suite of [chapter 5](./evaluate.mdx).

## Target state

- The uses the interface serves are listed, with the ones it does not serve.
- The scope is public data only, with the products named; confidential and embargoed data are excluded by design.
- Success criteria are written as checks on an answer: series, value, caveat, citation, refusal.
- A question set of real questions, per language, with expected tools, series, values, and behaviour, represents the scope.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Decide the uses and the scope. Write ten questions with expected answers. Confirm the API and catalog can answer them. |
| **AI-ready** | Write the success criteria and a question set of 30 to 50 questions per language, including questions to decline. Keep it in version control. |
| **AI-native** | Grow the question set from logged questions and the AI visibility check, and review the scope against usage each period. |

:::info[Running example]
The example organization serves its five published series to agents for
four uses: find a series, read its definition, fetch values for a period,
and compare periods. Eight questions represent the scope, two of which an
agent should decline: an inflation rate the organization does not publish,
and a regional value for a national-only series.
:::

## Recipes

<Recipe title="1.1 Decide the uses and the scope" level="Foundational" skills="Dissemination lead; developer" time="Half a day">

**Result:** a one-page statement of what the interface is for and what it
exposes.

1. List the uses, in the agent's terms: search for a series by meaning,
   read a series' definition and caveats, fetch values for an area and a
   period, resolve a place name to a code, list what is available.
   Analysis (growth rates, rankings) is a separate decision; the Data360
   server offers it as separate tools, and the simplest server leaves it to
   the client.
2. Set the scope: public data only. Microdata expose metadata and never
   data through the interface ([chapter 6 of the microdata cookbook](/cookbook/microdata-documentation/access)).
   Name the products in scope at launch.
3. State what the interface does not do: estimate, forecast, or combine
   series into new figures. The agent reports what the organization
   publishes.
4. Confirm that the API and catalog answer the uses: a series record with
   definition and unit, values by area and period, code lists. Gaps go to
   the [dissemination cookbook](/cookbook/ai-ready-dissemination/).

**What this does not do.** The scope statement is a decision; the tools of
[chapter 2](./tools.mdx) enforce it, and the safety checks of
[chapter 4](./safety.mdx) verify that nothing outside it is reachable.

</Recipe>

<Recipe title="1.2 Write the success criteria and the question set" level="AI-ready" skills="Dissemination officer; speakers of each supported language" time="One day for the first 30 questions">

**Result:** a question set that states, for each question, which tools
should be called, which series and value are expected, and whether the
agent should answer or decline.

1. Write the criteria for a correct answer: the right series, the right
   value within rounding, the period and unit stated, the caveat repeated
   when the record has one (provisional, break), a source URL and release
   date cited, and a refusal when the data are not published or not
   available at the requested level.
2. Collect questions from search logs, help-desk tickets, and the AI
   visibility check, and add paraphrases, each supported language, and
   questions to decline. The running example:

```csv file=../../website/static/cookbook-files/serving-statistics-to-agents/agent_questions.csv
```

3. For each question, record the expected tools, series, value, and
   behaviour; a question with no expected value is a metadata question.
4. Keep the set in version control; it is the suite of
   [chapter 5](./evaluate.mdx).

**What this does not do.** Eight questions describe the scope; a measure
needs 30 to 50 per language. The questions in languages other than English
are marked for native-speaker review in the file.

</Recipe>

## Implementation options

- **Uses:** the four core uses above; analysis and visualization tools as an explicit addition (the Data360 server's `data360_summarize_data`, `data360_rank_countries`, `data360_get_viz_spec`).
- **Scope:** public data; metadata for everything; confidential data never. The AI-use policy of the dissemination cookbook records the decision.
- **Question set:** the same format as the dissemination cookbook's known-item set, extended with expected tools and behaviour.

## World Bank examples

- The [Data360 MCP server](https://github.com/worldbank/data360-mcp) scopes its tools to discovery, metadata, data retrieval, analysis, and visualization over public indicators, and guides the agent with a system-prompt resource.
- The program's [MCP page](/docs/mcp/) describes the uses an MCP server for development data serves.

## Common mistakes

- **Scope by omission.** Whatever the API exposes is in scope unless the server restricts it; licensed data behind a reachable endpoint are a breach.
- **Tools before questions.** Without a question set, the tools are designed for the developer's guesses.
- **Analysis in the server by default.** Derived figures carry the organization's name; they are a deliberate addition with their own checks.
- **One language.** Questions arrive in the national language; the set includes it.

## Verification

- **Scope:** the statement names the products, the uses, and the exclusions; the AI-use policy references it.
- **Question set:** at least 30 questions per language with expected tools, series, values, and behaviour; at least a fifth are questions to decline or metadata questions.
- **Coverage:** every use in the statement is represented by questions.
