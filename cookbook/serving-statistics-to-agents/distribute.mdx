# 8. Distribution to clients and developers

**Question:** How do users and developers connect to the interface?

## Rationale

A server nobody can find or configure serves nobody. Users of assistants
need a configuration they can paste; developers of agents need the
manifest, the guidance, the terms, and an endpoint they can test;
registries need a listing in their format. The pieces are small, and
their absence is the usual reason a working server has no traffic. A
developer page that holds them all, a listing where clients look, and a
support channel are the distribution of the interface.

## Target state

- A developer page publishes the endpoint, the client configurations, the manifest, the guidance resource, the tiers and terms, the changelog, and the support contact.
- The server is listed in the MCP registry with a valid listing, and in the organization's catalog.
- Configurations are tested with the common assistants and frameworks each release.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Publish the developer page with the endpoint, one client configuration, the terms, and a contact. |
| **AI-ready** | Add configurations for the common assistants and frameworks; publish the listing in the registry and check it; test the configurations each release. |
| **AI-native** | Publish the server package for local use beside the hosted endpoint; keep the listing and the configurations updated automatically from the manifest and the version. |

:::info[Running example]
The example server's developer page holds a configuration for an
assistant that connects over streamable HTTP with a bearer token, and
the registry listing names the hosted endpoint and a package for local
use. The listing check passes with no errors or warnings.
:::

## Recipes

<Recipe title="8.1 Publish the client configurations" level="Foundational" skills="Developer; dissemination officer" time="Half a day; tested each release">

**Result:** users can connect their assistant by pasting a configuration,
and developers can connect a framework with a few lines.

1. Publish the configuration for the common clients; the running
   example's configuration for a desktop assistant:

```json file=../../website/static/cookbook-files/serving-statistics-to-agents/client_config_example.json
```

2. Cover the clients the organization's users have: desktop assistants
   that take an `mcpServers` block, assistants that add servers through a
   settings page, coding tools, and agent frameworks (the Python SDK's
   client for custom agents). The Data360 server documents connection
   from several clients, which is the pattern.
3. State for each: the transport (streamable HTTP for the hosted
   endpoint; stdio for the package), where the key goes, and the first
   question to try.
4. Test every configuration with each release ([chapter 9](./operate.mdx))
   and keep a screenshot or a transcript of the first question's answer.

**What this does not do.** Configurations change with the clients. The
page says which client versions were tested and when.

</Recipe>

<Recipe title="8.2 List the server in the registry and the catalog" level="AI-ready" skills="Developer" time="Half a day">

**Result:** the server appears where clients and developers look for
servers, with a listing that passes the format check.

```python file=../../website/static/cookbook-files/serving-statistics-to-agents/check_server_listing.py
```

```bash
python check_server_listing.py server_listing.json
```

Output for the running example:

```text
server_listing.json: org.example.stats/statistics-example 1.0.0; 1 remote(s), 1 package(s)
0 error(s), 0 warning(s)
```

1. Write the listing
   ([server_listing.json](pathname:///cookbook-files/serving-statistics-to-agents/server_listing.json)):
   a reverse-DNS name under the organization's domain, the version, a
   title and a description, the website, the repository, the hosted
   remote with its transport and URL, and the package where one exists.
2. Run the check; publish to the [MCP registry](https://registry.modelcontextprotocol.io/)
   with its publisher tool, which validates against the dated schema and
   verifies the namespace.
3. List the server in the organization's own catalog and developer page,
   and in the AI component register; update the listing's version with
   each release.

**What this does not do.** A listing makes the server findable; the
registry does not vouch for it. Users decide to trust the organization's
domain, which is why the namespace and the website matter.

</Recipe>

<Recipe title="8.3 Publish the developer page and the support channel" level="Foundational" skills="Dissemination officer; developer" time="Half a day; ongoing">

**Result:** one page with everything a user or developer needs, and a way
to reach the organization.

1. Put on the page: the endpoint and transport; the client
   configurations; the manifest ([chapter 2](./tools.mdx)) and the
   guidance resource ([chapter 3](./context.mdx)); the tiers, terms, and
   registration ([chapter 5](./access.mdx)); the changelog and the
   deprecation policy ([chapter 9](./operate.mdx)); the licence and the
   citation form; the support contact.
2. Add a "first question" walkthrough with the expected answer, so that a
   user can tell a working connection from a broken one.
3. Open a support channel (an address, an issue tracker) and state the
   response time; route bug reports on answers to the evaluation
   ([chapter 7](./evaluate.mdx)) and misquotes to the
   [monitoring cookbook](/cookbook/monitoring-data-use/act).
4. Link the page from the catalog's API documentation and from each
   series page.

**What this does not do.** A developer page documents the interface; the
documentation of the data (definitions, methods) stays in the catalog,
which the metadata tool returns.

</Recipe>

## Implementation options

- **Configurations:** `mcpServers` blocks for desktop assistants; settings-page instructions for others; SDK snippets for frameworks.
- **Listing:** the registry's server.json format and publisher tool; the organization's catalog and developer page.
- **Package:** a PyPI or npm package for local use with stdio transport, beside the hosted endpoint.
- **Support:** an address or tracker, with response time stated.

## World Bank examples

- The [Data360 MCP server](https://github.com/worldbank/data360-mcp) documents connection from several clients and publishes its endpoint and configuration.
- The program's [MCP page](/docs/mcp/) describes the interfaces and how to connect to them.

## Resources

- [MCP registry](https://registry.modelcontextprotocol.io/): the official registry of servers, with the publisher tool and the server.json format.
- [server.json reference](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/generic-server-json.md): the fields of a listing (name, version, repository, packages, remotes).
- [MCP clients](https://modelcontextprotocol.io/clients): the list of client applications and the features each supports (tools, resources, prompts).
- [Server listing](pathname:///cookbook-files/serving-statistics-to-agents/server_listing.json) and [listing check](pathname:///cookbook-files/serving-statistics-to-agents/check_server_listing.py): the running example's listing and the check.
- [Client configuration](pathname:///cookbook-files/serving-statistics-to-agents/client_config_example.json): the running example's configuration for a desktop assistant.

## Common mistakes

- **A server with no page.** Working and unused.
- **One configuration.** Users have different assistants; publish the ones they use and say which were tested.
- **A listing never updated.** A stale version in the registry sends clients to tools that no longer exist.
- **Support nobody reads.** State the response time and route reports to the evaluation and the monitoring.

## Verification

- **Page:** a new user connects from the page alone and gets the expected first answer.
- **Listing:** the check passes; the registry entry shows the current version.
- **Configurations:** each tested with the current release, with the date recorded.
- **Support:** reports received in the period have a recorded response.
