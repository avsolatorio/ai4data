# 7. Monitoring of data use

**Question:** Can we see how our data are used, including by AI systems?

## Rationale

Download counts show only part of data use. Statistics are cited in
research papers, policy documents, news stories, and, increasingly, in the
answers of AI systems. Knowing where and how they appear helps an organization
prioritize datasets, find misuse, and show the value of its work.

## Target state

- Datasets have consistent names and identifiers, which makes mentions easier to match.
- The organization tracks mentions in publications and reports as well as downloads.
- It checks how AI systems describe its statistics, and corrects the source material when answers are wrong.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Publish a recommended citation and a persistent identifier (a DataCite DOI where possible) for each dataset. Keep web and API logs, and count views and downloads following the COUNTER Code of Practice for Research Data, which separates machine access from regular access. |
| **AI-ready** | Search publication sources for dataset names and identifiers on a schedule. Keep a table of dataset name variants and acronyms. Review a sample of results by hand. |
| **AI-native** | Extract dataset mentions from documents with a named-entity model, harmonize variants to canonical identifiers, and report use by dataset, topic, and geography. Periodically ask AI systems a fixed set of questions and record how they cite or misquote the organization. |

:::info[Running example]
The organization's labour force survey is cited as "LFS", "the labour survey",
and "Labour Force Survey 2025" in reports. The name table in recipe 7.1 maps
all three to one identifier, and the monthly AI check in recipe 7.3 records
whether assistants cite the organization when asked for the unemployment rate.
:::

## Recipes

<Recipe title="7.1 Publish a canonical name table" level="Foundational" skills="Dissemination staff" time="Half a day">

**Result:** one list of the names people use for each dataset, which
makes mentions in documents matchable and tells users what to write.

The table has one row per dataset, with the identifier, the official
name, the acronym, and the other forms found in documents, separated by
`;`:

```csv
canonical_id,canonical_name,acronym,variants
LFS,Labour Force Survey,LFS,labour survey;labor force survey;LFS 2025;quarterly labour survey
HBS,Household Budget Survey,HBS,household survey;budget survey;HBS 2021
```

1. Start from the datasets with the most downloads.
2. Add variants as they are found in documents (recipe 7.2 produces
   them).
3. Publish the table with the recommended citation and the DOI from
   [chapter 5](./trust.mdx), and use the canonical name everywhere the
   organization writes. A DOI makes citations countable: DataCite
   collects citations of DOIs from the literature, which gives a second
   source of use next to text mining.

**What this does not do.** The table makes mentions matchable and finds
none. The extraction of recipe 7.2 and the
[monitoring cookbook](/cookbook/monitoring-data-use/) use it, and the
variants column grows from what they find.

</Recipe>

<Recipe title="7.2 Find mentions in publications" level="AI-ready" skills="Analyst; Python for the automated version" time="One day a quarter by hand; one week to automate">

**Result:** a list of the documents that use each dataset, by year and
type of document, with a measured accuracy.

1. By hand: search a few sources (a national research repository, a
   publications database, the government's document site) for each
   canonical name and acronym once a quarter. Record the document, the
   year, the type, and the dataset.
2. Automated: run a zero-shot named-entity model over the text of
   collected documents with labels such as "dataset" and "survey". Such
   a model finds names of a given kind in text without training on the
   organization's documents. Match the found names to the canonical
   table by string similarity. The program's
   [Monitoring of Data Use](/docs/data_use/) page documents this
   pipeline with GLiNER and its harmonization step, and the
   [monitoring cookbook](/cookbook/monitoring-data-use/) gives the full
   workflow.
3. Measure: label 50 documents by hand and compute the precision and
   recall of the extraction. Report use counts with that accuracy next
   to them.

**What this does not do.** Hand search finds what the searcher thinks
to look for; the extraction finds what the collected documents contain.
Neither sees documents nobody collected, and the accuracy measured in
step 3 holds for the labelled documents' types and languages.

</Recipe>

<Recipe title="7.3 Run a monthly AI visibility check" level="AI-native" skills="Dissemination staff" time="Two hours a month">

**Result:** a record, over time, of whether AI assistants cite the
organization, quote the right numbers, and link to the right page.

The record is a CSV with one row per question per assistant per month:

```csv
date,assistant,question_id,cites_office,number_correct,link_resolves,notes
2026-10-01,assistant A,q04,yes,yes,yes,
2026-10-01,assistant B,q04,no,no,,quoted a 2023 figure from a third-party site
```

1. Fix ten questions that users ask about the organization's main
   indicators, in the national language and in English.
2. Each month, ask the same questions to two or three widely used
   assistants and record the answers in the form above.
3. When a number is wrong, check first whether the organization's own
   page and API show the current value clearly
   ([chapters 1](./find.mdx), [2](./retrieve.mdx), and
   [5](./trust.mdx)). Most fixes are on the organization's side.
4. Treat the results as a sample that changes month to month. Report
   trends over several months, and avoid conclusions from one run.

**What this does not do.** Ten questions to two or three assistants
sample what assistants said in one month, and assistants change without
notice. Trends over several months are the evidence; a single run is an
anecdote.

</Recipe>

## Implementation options

- **Citation design:** one canonical dataset name, a short acronym, and a persistent identifier (DataCite DOI) reduce ambiguity and make citations countable.
- **Usage counts:** the [COUNTER Code of Practice for Research Data](https://coprd.countermetrics.org/), developed with [Make Data Count](https://makedatacount.org/), gives rules for logging views and downloads, filtering repeated requests, and reporting machine access separately from regular access. Following it makes an organization's counts comparable with those of data repositories.
- **Log analysis:** user-agent strings and request patterns identify many crawlers and automated clients. Record them in a separate category and report human and automated use separately.
- **Mention extraction:** zero-shot named-entity models can find dataset mentions in PDF and web text. A matching step maps variants such as an acronym and a full title to one identifier.
- **AI visibility check:** a fixed set of questions run against several assistants, repeated on a schedule.

## Common mistakes

- **Counting downloads as use.** Downloads include crawlers, test scripts, and repeat visits. Separate them and add mentions.
- **One name per dataset.** Reports use acronyms and informal names. The variants table is the matching key.
- **Reading one AI check as a trend.** Assistant answers vary between runs. Several months of the same questions make a trend.
- **Blaming the assistant.** When an assistant quotes an old figure, the current one was often hard to find or retrieve. Fix the source first.

## Verification

- **Extraction accuracy:** label a sample of documents by hand and measure precision and recall of the extraction.
- **Harmonization accuracy:** check a sample of matched variants against the canonical identifier.
- **Repeatability:** run the AI visibility check twice in a week and note how much the results differ before drawing conclusions.
