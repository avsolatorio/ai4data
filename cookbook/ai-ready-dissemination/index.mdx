# Practical Guide to AI-Ready Data Dissemination

**A cookbook for national statistical organizations.** Version 0.1 (working draft), October 2026.

:::note[Working draft]
This guide is a working draft from the AI for Data – Data for AI program. It
collects practical approaches and open standards. It is not an international
guideline. Comments and corrections are welcome as
[GitHub issues](https://github.com/worldbank/ai4data/issues), and the
[contribute](./contribute.md) page explains how to propose a recipe.
:::

People increasingly reach statistics through AI systems: search assistants,
chatbots, and analysis tools. These systems read the metadata, web pages, and
APIs that a statistical organization publishes. When those are incomplete,
ambiguous, or hard to retrieve, the systems return the wrong series, mix up
definitions, or quote numbers without a source.

This guide is organized around nine questions an organization can ask about its own
dissemination system. Each chapter explains why the question matters, what a
good answer looks like, and gives **recipes**: tasks with a defined result,
the skills and time they need, and the code or template to do them.

The recipes build on published standards: SDMX for aggregate data, DDI for
microdata, ISO 19115 for geospatial data, Dublin Core for documents, DCAT
and schema.org for catalogs, DataCite for identifiers, and the World Bank's
own metadata schemas for records. The [standards page](./standards.md)
lists each one, where the World Bank uses it, and where it appears in the
guide. The chapters follow one indicator catalog as a running example; the
[Application by data type](./data-types.md) page shows how each question and recipe
applies to survey microdata, geospatial data, documents, and tables, with a
record and a profile for each.

:::tip[AI readiness does not require generative AI]
Many of the highest-value steps are ordinary data practice: complete
metadata, open structured data, stable identifiers, and documented APIs. These
steps help human users and conventional search as well. A chatbot is an
optional later layer, and chapters 4 and 5 explain what has to be in place
before one is safe to run.
:::

## Self-assessment

The [self-assessment](./start-here.mdx) takes about five minutes. It places
an organization at a level in each chapter and suggests a reading order.

## Chapters and questions

| Chapter | Question for a statistical organization | Practical topics |
|---|---|---|
| [1. Find](./find.mdx) | Can people and AI find our statistics? | Metadata completeness, indexing, DCAT and schema.org, semantic search, multilingual metadata |
| [2. Retrieve](./retrieve.mdx) | Can AI retrieve our data reliably? | Open formats, APIs, stable identifiers, machine-readable access, MCP |
| [3. Understand](./understand.mdx) | Can AI understand what the numbers mean? | Units, concepts, classifications, method notes, SDMX, DDI, code lists |
| [4. Ask](./ask.mdx) | Can users ask questions naturally? | Natural-language search, retrieval-augmented generation, conversational interfaces, multilingual access |
| [5. Trust](./trust.mdx) | Can answers be trusted? | Provenance, citation, numeric verification, grounding, freshness |
| [6. Evaluate](./evaluate.mdx) | Can we tell whether it works? | Retrieval benchmarks, hallucination tests, answer accuracy, multilingual evaluation |
| [7. Monitor use](./monitor-use.mdx) | Can we see how our data are used? | Dataset mention detection, citation tracking, AI visibility |
| [8. Govern](./govern.mdx) | Can we operate this responsibly? | Governance, human oversight, security, privacy, model choice, vendor dependence |
| [9. Sustain](./sustain.mdx) | Can we maintain it? | Architecture, open standards, small and open models, cost, skills, lifecycle |

These questions follow the same path as the program's
[AI-ready data framework](/docs/ai-ready-framework): find the right data,
retrieve it with context, interpret it, and verify the result.

## Maturity levels

Each chapter describes three levels. An organization can sit at different levels in
different chapters, and the first level is a complete, useful state on its
own.

| Level | Meaning |
|---|---|
| **Foundational** | Data and metadata are published in open, documented formats that a person can download and that a crawler can read. |
| **AI-ready** | Data and metadata are structured, identified, and accessible through documented interfaces, so that software, including AI systems, can use them without manual steps. |
| **AI-native** | The organization offers AI-oriented interfaces such as semantic search or an agent protocol, with provenance and verification built in. |

For access, as an example:

- **Foundational:** downloadable CSV files with a metadata page.
- **AI-ready:** a documented REST API, stable identifiers, and structured metadata.
- **AI-native:** semantic discovery, a standard agent interface such as MCP, and provenance on every answer.

## Running example

The recipes use one small, fictional catalog so that each chapter picks up
where the previous one ends. The example organization publishes five series:

| id | title | unit |
|---|---|---|
| `FS_UNDERNOURISH_PCT` | Prevalence of undernourishment | % of population |
| `ED_PRIMARY_NER_PCT` | Net enrolment rate in primary education | % of age group |
| `HE_U5_MORT_RATE` | Under-five mortality rate | deaths per 1000 live births |
| `LF_UNEMP_PCT` | Unemployment rate | % of labour force |
| `PV_HEADCOUNT_NPL_PCT` | Poverty headcount ratio at national poverty line | % of population |

One record has an empty definition on purpose, so that the completeness
report in chapter 1 and the search scores in chapter 6 have something to
find. The catalog file uses the field names of the
[World Bank indicator metadata schema](https://github.com/worldbank/metadata-schemas)
(`idno`, `name`, `definition_long`, `measurement_unit`, `periodicity`, and
so on), and the values file uses SDMX cross-domain concept names (`SERIES`,
`REF_AREA`, `TIME_PERIOD`, `OBS_VALUE`, `OBS_STATUS`, `UNIT_MEASURE`). The
catalog, the values, and every script in this guide are in the files list
below. All values are invented.

## Scope of the examples

The examples are small on purpose: five series, fifteen test questions,
and single-file scripts with no dependencies beyond the standard library
and `jsonschema`, so that a reader can run them in an afternoon and see
the shape of each check. They are starting points. Each recipe
ends with a **What this does not do** note that says where the example
stops and what the full version adds, and points to the program's tools
where one exists. Treat a recipe as done when the organization's own data pass
the organization's own version of the check, with the profile, question set, and
rules that the organization has agreed.
