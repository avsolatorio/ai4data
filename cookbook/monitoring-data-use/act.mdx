# 9. Action on the results

**Question:** Can the results improve the data and their documentation?

## Rationale

Monitoring earns its cost when the results change something: which
datasets get documentation work first, which misquotes are corrected,
which documents and datasets are linked in the catalog, and which products
are argued for at budget time. The chapter turns the report into those
decisions.

## Target state

- Documentation and dissemination work is prioritized by use and by the gaps the report shows.
- Misquoted figures found in documents and AI answers are followed up, with the fix on the organization's side where the cause is there.
- Document records and dataset pages link to each other from the results, and confirmed variants flow back to the names table.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Review the report each period and decide which products to continue, improve, or promote. |
| **AI-ready** | Prioritize the documentation work of the other cookbooks by use. Check quoted figures against the catalog and follow up misquotes. Add "used in" to dataset pages. |
| **AI-native** | Feed results into the catalog automatically: document records' data sources, dataset pages' citations lists, names table variants, and the question sets of the evaluation suites. |

:::info[Running example]
The report shows the household budget survey used in research, the
labour force survey in media, and its unemployment rate in policy. The nutrition strategy quotes the
undernourishment figure correctly; the regional outlook mentions a food
security report without using it. The example organization decides to
complete the labour force survey's variable documentation first, because it
is the dataset most used outside research, where users rely on the record
alone.
:::

## Recipes

<Recipe title="9.1 Prioritize documentation and dissemination work by use" level="AI-ready" skills="Dissemination lead" time="Half a day per period">

**Result:** the work lists of the other cookbooks ordered by the use the
report shows, and the gaps it shows acted on.

1. For each dataset, put the use counts next to its documentation status:
   the completeness check of the
   [dissemination cookbook](/cookbook/ai-ready-dissemination/find) and, for
   surveys, the dictionary check of the
   [microdata cookbook](/cookbook/microdata-documentation/variables).
2. Order the work: datasets used most and documented least first; among
   them, those used outside research first, since policy and media users
   read the record and nothing else.
3. Read the gaps: a dataset produced and never mentioned is a
   discoverability or relevance signal; a dataset used only with another
   organization's data (co-use) is a candidate for a joint product or a
   crosswalk.
4. Record the decisions with the report, so that the next period shows
   whether use changed where work was done.

**What this does not do.** Use measures demand as it was; it does not show
demand that better documentation would create. Datasets never mentioned
need a judgement about why.

</Recipe>

<Recipe title="9.2 Follow up misquoted figures" level="AI-ready" skills="Dissemination officer" time="One hour per period plus follow-up">

**Result:** figures quoted from the data in documents and AI answers are
checked against the catalog, and the organization's own causes are fixed
first.

1. For mentions with a usage context that quotes a figure (the extractor's
   context window shows it), compare the figure with the catalog value for
   the dataset, period, and geography, with the tolerance of the number
   check in the [dissemination cookbook](/cookbook/ai-ready-dissemination/trust).
2. Do the same for the AI visibility check: wrong figures, wrong periods,
   missing citations.
3. For each misquote, check the organization's side first: was the current
   figure findable, retrievable, and clearly labelled with its period and
   unit? Most fixes are there. Then contact the author or publisher where
   the error matters.
4. Log misquotes by dataset and cause; a dataset misquoted often needs its
   page and its API response looked at.

**What this does not do.** The check finds figures that differ from the
catalog. A figure that differs because the document used an earlier
vintage is correct for its date; the revisions log says so.

</Recipe>

<Recipe title="9.3 Close the loop in the catalog" level="AI-native" skills="Catalog administrator; developer" time="One week to set up">

**Result:** the results of monitoring become part of the records: documents
link to the datasets they use, dataset pages list the documents that use
them, and the names table grows from confirmed variants.

1. For each matched mention with `is_used`, add the dataset to the
   document's record (`data_sources` in the World Bank document schema)
   where the document is in the organization's catalog.
2. On each dataset page, show "used in" from the harmonized mentions, as
   the Microdata Library's citations pages do, with the document, year,
   and type.
3. Write confirmed variants back to the names table and to the series
   record's `aliases`, and add misquoted questions to the evaluation
   question set of the dissemination cookbook.
4. Expose the links through the catalog API, so that an AI system
   answering about a dataset can cite the documents that use it.

**What this does not do.** Automatic links carry the extractor's
precision. Links on public pages are added for exact and reviewed matches
only; phrase and fuzzy matches wait for review.

</Recipe>

## Implementation options

- **Prioritization:** use counts joined with the completeness and dictionary checks of the other cookbooks.
- **Misquote checks:** the number verification approach of Proof-Carrying Numbers applied to quoted figures; the revisions log for vintages.
- **Catalog links:** `data_sources` in document records, citations lists on dataset pages, `aliases` in series records; NADA's citations feature.
- **Feedback to evaluation:** misquoted questions added to the question sets that score search and answers.

## World Bank examples

- The [Microdata Library](https://microdata.worldbank.org/citations) lists citing publications per study.
- [Proof-Carrying Numbers](https://arxiv.org/abs/2509.06902) is the number verification that recipe 6.2 applies to quoted figures.
- The [operationalizing the assessment](/ai-readiness-in-practice) page places monitoring in the dimensions of the AI-readiness assessment.

## Resources

- [Proof-Carrying Numbers](https://arxiv.org/abs/2509.06902): the program's method for checking a quoted figure against its source, applied to misquotes.
- [NADA](https://nada.ihsn.org/): the catalog's citations feature, where "used in" lists are published per study.
- [World Bank metadata schemas](https://github.com/worldbank/metadata-schemas): `data_sources` in document records and `aliases` in series records, the fields that close the loop.
- [Findability chapter of the dissemination cookbook](/cookbook/ai-ready-dissemination/find) and [chapter 3 of the microdata cookbook](/cookbook/microdata-documentation/variables): the completeness and dictionary checks that use counts prioritize.
- [Evaluation chapter of the dissemination cookbook](/cookbook/ai-ready-dissemination/evaluate): the question sets that misquoted figures feed.

## Common mistakes

- **Reports without decisions.** The period ends and nothing is different.
- **Blaming the author first.** Most misquotes trace to a figure that was hard to find or unlabelled on the organization's side.
- **Linking unreviewed matches on public pages.** A wrong "used in" entry is a public error.
- **Prioritizing by research use alone.** Policy and media users depend most on the record.

## Verification

- **Decisions:** each period's report has a recorded set of decisions and, next period, their effect.
- **Misquotes:** logged with cause and follow-up; the share caused by the organization's own side falls over time.
- **Links:** "used in" lists and `data_sources` present for reviewed matches; aliases updated.
