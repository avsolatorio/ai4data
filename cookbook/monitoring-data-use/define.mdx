# 1. Definition of use

**Question:** What counts as use of the data?

## Rationale

"Use" covers very different things: a paper that builds its analysis on a
survey, a strategy that sets a target against an indicator, an article that
quotes a release, a report that lists a dataset among its sources, and an
AI answer that states a figure. Counting them together gives a number
without a meaning. A definition that separates these, and a names table
that says which dataset each mention refers to, come before any tool.

## Target state

- A written typology distinguishes mention from use, and primary use from secondary and background use.
- Every dataset has one canonical name, one acronym, one identifier, and the list of variants people write, in a table the catalog and the citations share.
- The unit of counting (documents, by default) and the scope (which sources, which period, whether the organization's own publications are included) are stated.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Write the typology. Build the canonical names table for the most-used datasets. Decide the unit and scope. |
| **AI-ready** | Extend the table to the whole catalog with identifiers and variants found in documents. Publish the recommended citation on every dataset page. Record the typology in the extraction's usage fields. |
| **AI-native** | Maintain the table from the monitoring results, with new variants reviewed and added, and expose it through the catalog so that other systems match the same names. |

:::info[Running example]
The example organization's table has six datasets with their acronyms and
the variants found so far, including "the labour survey" and
"unemployment rate from the LFS". The typology marks a mention as used
when the document builds on the data and as background when it cites the
data as context.
:::

## Recipes

<Recipe title="1.1 Adopt a typology of use" level="Foundational" skills="Dissemination lead" time="Half a day">

**Result:** a one-page definition that every count and report refers to.

1. Distinguish a **mention** (the dataset is named or referred to) from
   **use** (the document's analysis, decision, or statement depends on
   the data). The program's extractor records this as the `is_used` flag.
2. Within use, distinguish **primary** (the main source of the analysis),
   **secondary** (combined with another main source), and **background**
   (cited as context). The extractor records it as `usage_context`.
3. Treat **named** mentions ("Household Budget Survey 2021") and
   **unnamed** mentions ("the labour survey") separately; unnamed
   mentions need harmonization and are less certain.
4. Add the uses that documents do not show: downloads and API calls, which
   access statistics cover ([chapter 5](./report.mdx)), and AI systems'
   answers, which the AI visibility check covers.

**What this does not do.** A typology states categories; applying them is
a judgement the extractor makes with a confidence and a person confirms on
a sample ([chapter 3](./detect.mdx)).

</Recipe>

<Recipe title="1.2 Build the canonical names table" level="Foundational" skills="Dissemination officer" time="Half a day for the main datasets; ongoing additions">

**Result:** one row per dataset with the name, acronym, producer,
identifier, and variants, which detection, harmonization, and the catalog
all use.

```csv file=../../website/static/cookbook-files/monitoring-data-use/canonical_names.csv
```

1. Start from the datasets with the most downloads and the flagship
   products (surveys, censuses, main indicators, main reports).
2. Use the catalog's identifiers (`idno`, DOI) as `dataset_id`, so that a
   matched mention links to the record.
3. Add variants as they are found: acronyms with and without years,
   informal names, translations, and misspellings that recur.
4. Publish the recommended citation on each dataset page in the catalog
   ([chapter 5 of the dissemination cookbook](/cookbook/ai-ready-dissemination/trust));
   the citation uses the canonical name, which makes future mentions
   matchable.

**What this does not do.** The table lists the organization's own data.
Other organizations' datasets that appear alongside (the Demographic and
Health Survey, the World Development Indicators) are tracked as co-use in
[chapter 4](./harmonize.mdx), without a row here.

</Recipe>

<Recipe title="1.3 Decide the unit and the scope" level="Foundational" skills="Dissemination lead" time="One hour">

**Result:** a stated unit of counting and a stated scope, so that reports
can be compared over time.

1. Count **documents**, one per document per dataset, as the default
   unit; a document that mentions a survey five times is one use. Keep
   the mention count as a secondary figure.
2. State the **sources** in scope (chapter 2 lists them), the **period**,
   and whether the organization's own publications are included (they are
   usually excluded from use counts and tracked separately).
3. State the **languages** covered; a source in the national language
   needs the extractor tested in that language.
4. Record the decisions with the typology; a change in scope is a break
   in the series of reports.

**What this does not do.** The unit and scope define what is counted. The
coverage of the sources ([chapter 2](./collect.mdx)) and the recall of the
extractor ([chapter 3](./detect.mdx)) decide what is found, and both are
reported with the counts.

</Recipe>

## Implementation options

- **Typology:** the extractor's fields (`is_used`, `usage_context`, `dataset_tag`) as the recorded form; a one-page definition as the human form.
- **Names table:** a CSV under version control, or the catalog's own identifiers and aliases exported; the series record's `aliases` field in the World Bank schema holds variants.
- **Identifiers:** catalog identifiers and DataCite DOIs; a DOI makes citations countable through DataCite as well as through text mining.

## World Bank examples

- [Monitoring of Data Use](/docs/data_use/) records the usage flag and context per mention and harmonizes name variants ("WDI", "World Development Indicators", "World Bank Development Data") to one identifier.
- The [dissemination cookbook](/cookbook/ai-ready-dissemination/monitor-use) places the canonical names table and the recommended citation at the foundational level of its monitoring chapter.

## Common mistakes

- **Counting mentions as use.** A dataset listed in a bibliography and a dataset the analysis depends on are different uses.
- **A table without identifiers.** Matched mentions cannot be linked to records or counted with DataCite citations.
- **Scope that moves.** Adding a source without saying so makes a rise in use look like growth.
- **One language.** Mentions in the national language go unfound if the table and the extractor are English-only.

## Verification

- **Typology:** two staff classify twenty mentions independently and agree on most; disagreements refine the definitions.
- **Names table:** every flagship dataset has a row with an identifier and at least three variants.
- **Citations:** every dataset page shows the recommended citation with the canonical name.
