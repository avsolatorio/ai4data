# 3. Formal citations through identifiers

**Question:** Can citations be counted through DOIs and identifiers?

## Rationale

When a dataset has a DOI and a paper cites it in its reference list, the
citation is recorded by the identifier services without any text mining:
DataCite records the link when the publisher or the repository registers
it, Crossref holds the reference lists of articles, OpenAlex indexes
referenced works, and the Scholix framework exchanges dataset-literature
links between them. For an organization whose datasets carry DOIs, these
services give a citation count that is cheap, reproducible, and
comparable with other repositories.

The count is partial. Many authors name a survey in the text and cite the
report, or cite nothing; many publishers do not deposit references; policy
documents and news have no reference lists. The identifier services and
the text mining of [chapters 6](./detect.mdx) and [7](./harmonize.mdx)
find different parts of the same use, and merging them shows how much
each misses.

## Target state

- Every dataset the organization monitors has a DOI or another identifier that the services resolve, and the identifier is on the dataset page with a citation format.
- Citation events are collected from the identifier services on a schedule and merged by citing document.
- The merged list is compared with text mining, and documents found by one route only are reviewed and, where an identifier is missing, fixed.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Register DOIs for the main datasets and put the citation format on each dataset page. Look up citations in DataCite Commons and OpenAlex by hand each quarter. |
| **AI-ready** | Collect citation events from DataCite, Crossref, and OpenAlex through their APIs on a schedule; merge them with the script of this chapter; report per dataset. |
| **AI-native** | Compare identifier citations with text-mined mentions each run; feed the identifier-only documents to the collection of [chapter 4](./collect.mdx) and the mining-only documents to the DOI registration backlog. |

:::info[Running example]
Twelve citation events for four datasets from DataCite, Crossref,
OpenAlex, and the text mining of later chapters. They merge into seven
citing documents; two were found both through identifiers and in the
text, two only by text mining (a policy document and a regional report
without reference lists), and one only by OpenAlex.
:::

## Recipes

<Recipe title="3.1 Register identifiers and publish the citation format" level="Foundational" skills="Catalog administrator" time="Half a day to set up; minutes per dataset">

**Result:** every monitored dataset has a DOI with metadata that names
the organization as publisher, and its page shows how to cite it.

1. Register DOIs through a DataCite member (a national library, a
   consortium, or the organization itself) with the dataset's title,
   creator (the organization), publisher, year, and resource type
   `Dataset`; add `relatedIdentifier` links to the report and to earlier
   versions.
2. Put the citation on the dataset page in a fixed format with the DOI
   ([dissemination cookbook, chapter 5](/cookbook/ai-ready-dissemination/trust)),
   and in the record's citation field, so that reference managers pick
   it up.
3. Where DOIs are not available, use the catalog's persistent identifier
   and register it with the services that accept it; the merge in recipe
   3.2 keys on whatever identifier the record carries.

**What this does not do.** A DOI makes citations countable; it does not
make authors cite. The citation format on the page, and the request in
the terms of use, are what change behaviour, slowly.

</Recipe>

1. Collect events on a schedule: DataCite's Event Data or the GraphQL API
   for the dataset DOIs (relation types such as `IsCitedBy`), Crossref's
   REST API for works whose references include the DOI, OpenAlex for
   works whose `referenced_works` include the dataset, and ScholeXplorer
   for Scholix links aggregated across services. Write each event with
   its source into the events file.
2. Add the text-mined mentions of [chapter 7](./harmonize.mdx) as events
   with source `text-mining`, so that the merge compares the routes.
3. Run the merge and read the result: unique citing documents per
   dataset, the share each source found, and the documents found by one
   source only.
4. Review the one-source documents: an identifier-only document is a
   paper the collection of [chapter 4](./collect.mdx) should contain; a
   mining-only document with a DOI is a paper whose reference was not
   deposited; a mining-only document without a DOI (a policy document)
   is use the services cannot see.

**What this does not do.** The merge keys on identifiers and leaves a
preprint and its journal version as two documents until a mapping joins
them. The services' coverage differs by discipline and publisher; the
comparison with text mining is the only coverage measure available.

</Recipe>

**Result:** citation counts per dataset in the use report, with their

1. Report unique citing documents per dataset and year, by source, with

2. State what the count covers: works with deposited references and

**What this does not do.** A citation count ranks datasets by scholarly
attention. It does not measure policy influence or media reach, which
the other chapters measure differently.

</Recipe>

## Implementation options

- **Identifiers:** DataCite DOIs through a member organization; the catalog's persistent identifiers as a fallback.
- **Sources:** DataCite Event Data and GraphQL API; Crossref REST API; OpenAlex API; ScholeXplorer for Scholix links; the Data Citation Corpus as an aggregate.
- **Merge:** the script in this chapter by identifier; a mapping table for preprint and version pairs.
- **Publication:** a "cited by" list on the dataset page; the citation count in the use report.

## World Bank examples

- The [Microdata Library](https://microdata.worldbank.org/) registers DataCite DOIs for its studies and publishes a [citations list](https://microdata.worldbank.org/citations) per study.
- The dissemination cookbook's [trust chapter](/cookbook/ai-ready-dissemination/trust) sets the citation format and the DOI on every dataset page.

## Resources

- [DataCite Event Data guide](https://support.datacite.org/docs/eventdata-guide): citation and usage events linked to DOIs, and how to query them.
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/): free, no sign-up; works, references, and funders by query.
- [OpenAlex](https://help.openalex.org/): an open index of works with referenced works and an API; the route for citations by non-DataCite publishers.
- [ScholeXplorer](https://scholexplorer.openaire.eu/): OpenAIRE's Scholix hub of dataset-literature links aggregated across services.
- [Data Citation Corpus](https://makedatacount.org/data-citation/): an aggregate of citations to research data from articles and other outputs.
- [DataCite metadata schema](https://schema.datacite.org/): the fields and `relatedIdentifier` relations a dataset DOI carries.

## Common mistakes

- **Counting one service.** Each covers a different set of publishers; merge them.
- **Datasets without identifiers.** Nothing to count; register DOIs first.
- **Citation count read as use.** It is scholarly reference-list use; the other chapters count the rest.
- **One-source documents ignored.** They are where the identifiers, the collection, and the coverage improve.

## Verification

- **Identifiers:** every monitored dataset resolves through its DOI with the organization as publisher.
- **Events:** the scheduled collection produces events from each configured service; the merge reports per source.
- **Comparison:** the overlap with text mining is reported each run; one-source documents are reviewed.
