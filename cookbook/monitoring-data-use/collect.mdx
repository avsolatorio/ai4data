# 4. Collection from scholarly sources

**Question:** Can the research documents that use the data be collected?

## Rationale

Research use is the best-indexed kind of use. Open scholarly indexes
hold the metadata, abstracts, and often the full text of articles,
working papers, and theses, with APIs that accept a search by name and by
reference. A collection built from them is where the text mining of
[chapter 6](./detect.mdx) finds the surveys named in the methods section
and the indicators quoted in the introduction, which the identifier
citations of [chapter 3](./citations.mdx) miss. The collection decides
what the monitoring can see, so its sources are listed, its documents
carry metadata, and its coverage is measured.

## Target state

- The scholarly sources in scope are listed with their terms and collection method.
- Documents are collected by name search and by reference on a schedule, deduplicated by identifier, and stored with metadata and a text layer.
- Coverage is measured as the share of a reference list of known research uses that the collection contains.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Search the main indexes by hand for the canonical names and acronyms each quarter; record the documents found with year, type, and source. |
| **AI-ready** | Query the indexes' APIs by name and by reference on a schedule; collect open full texts; store metadata and text; measure coverage against a reference list. |
| **AI-native** | Add sources from the results (journals and repositories that cite often); track coverage over time; feed identifier-only citations from chapter 3 into the collection automatically. |

:::info[Running example]
Two of the six collected documents come from an academic index: a journal
article and a working paper. Both have DOIs, open full texts, and
metadata; the working paper is also a citation event in chapter 3, and
the article's reference list is what the text mining confirms.
:::

## Recipes

<Recipe title="4.1 List the scholarly sources and their terms" level="Foundational" skills="Dissemination officer; librarian" time="Half a day">

**Result:** the list of indexes and repositories where research use of
the data appears, with the terms under which each can be queried and
its texts collected.

1. Open indexes:
   - [OpenAlex](https://help.openalex.org/): works, abstracts,
     referenced works, open-access locations, free API;
   - [Semantic Scholar](https://api.semanticscholar.org/api-docs/):
     papers and citations, an API with a key;
   - [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/):
     DOIs and deposited references;
   - [CORE](https://core.ac.uk/): open-access full texts.
2. National and institutional repositories: the national research
   repository, university theses collections, and the working paper
   series of the central bank, ministries, and research institutes,
   which are the heaviest users of national statistics.
3. International organizations' research series (the World Bank's
   [Policy Research Working Papers](https://www.worldbank.org/en/research),
   the IMF, regional development banks) where the country's data are
   used.
4. For each source, record the API or export, the rate limits, the text
   availability (abstract, open full text, closed), and the licence of
   the content.

**What this does not do.** Google Scholar has no API and its terms do
not allow collection. Its results serve the reference list by hand, and
the collection comes from the indexes above.

</Recipe>

<Recipe title="4.2 Collect texts by name search and by reference" level="AI-ready" skills="Developer" time="One to two weeks to set up; scheduled runs after">

**Result:** a collection of documents gathered from each source by two
routes (searching for the dataset's names, and asking for works that
cite its DOI), with metadata and text, and duplicates removed.

The collection is kept as a documents table with one row per document:

| Column | Meaning |
|---|---|
| `document_id` | The collection's own identifier |
| `title`, `year`, `type` | What the document is; `type` is journal article, working paper, policy document, news article, and so on |
| `source` | Where it was found (academic index, ministry site, news dataset) |
| `country` | The country the document concerns |

```csv file=../../website/static/cookbook-files/monitoring-data-use/documents.csv
```

1. Query by name: search each index for the canonical names, acronyms,
   and variants of [chapter 1](./define.mdx) in titles, abstracts, and
   full text where the index searches it. Record every hit with the
   query that found it.
2. Query by reference: for datasets and reports with DOIs, ask the
   index for works that reference them (OpenAlex referenced works,
   Crossref references, Semantic Scholar citations). These are the
   events of [chapter 3](./citations.mdx) and belong in the collection
   too.
3. Collect the open full text where the index gives a location
   (OpenAlex open-access locations, CORE, the repository's PDF), and
   the abstract otherwise. Closed texts stay out, and the coverage note
   says so.
4. Store each document with the fields above.
5. Deduplicate across sources by DOI, then by title and year for
   records without one. Keep every source that found the document.

**What this does not do.** Name search returns every document that
contains the words, including other countries' surveys with the same
name; the harmonization of [chapter 7](./harmonize.mdx) sorts them.
Full texts behind paywalls are out of reach, and the reference lists
still show the citations.

</Recipe>

<Recipe title="4.3 Produce the text layer and measure coverage" level="AI-ready" skills="Developer; dissemination officer for the reference list" time="One day to set up">

**Result:** every collected document has text the extractor can read,
and the organization knows what share of the research uses it already
knew about the collection contains.

1. Extract text per page with PyMuPDF (a Python library that reads
   PDFs), as the program's [document parser](/docs/data_use/) does.
   Keep the page structure, for the extractor's context windows and
   for the citation back to the page.
2. Build a reference list of known research uses: papers staff know,
   the citing documents of [chapter 3](./citations.mdx), and the
   "cited by" lists the organization already keeps.
3. Measure coverage as the share of the reference list present in the
   collection, per source, and report it with the counts.
4. Add sources where coverage is low, and re-measure.

**What this does not do.** Coverage against a reference list measures
the known uses. The measure is a lower bound, and the report says so.

</Recipe>

## Implementation options

- **Indexes:** OpenAlex (open, API), Semantic Scholar (API), Crossref (references), CORE (open full texts); national and institutional repositories through OAI-PMH or exports.
- **Queries:** by name (canonical names and variants) and by reference (DOIs); both recorded with each document.
- **Text:** open full texts collected; abstracts otherwise; PyMuPDF for the text layer; the same layer the [documents cookbook](/cookbook/data-from-documents/inventory) produces.
- **Deduplication:** DOI first, then title and year; sources kept per document.

## World Bank examples

- [Monitoring of Data Use](/docs/data_use/) parses PDFs with PyMuPDF and keeps page structure for extraction.
- The [Microdata Library](https://microdata.worldbank.org/citations) publishes a citations list per study, built from collected publications.

## Resources

- [OpenAlex](https://help.openalex.org/): works, abstracts, referenced works, and open-access locations through a free API; the first source to connect.
- [Semantic Scholar Academic Graph API](https://api.semanticscholar.org/api-docs/): paper search and citation graphs, with an API key for higher rates.
- [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/): DOIs and deposited reference lists, free and without sign-up.
- [CORE](https://core.ac.uk/): aggregated open-access full texts from repositories, with an API.
- [OAI-PMH](https://www.openarchives.org/pmh/): the harvesting protocol most repositories expose, for national and institutional collections.
- [PyMuPDF](https://pymupdf.readthedocs.io/): page-level text extraction for the collected PDFs.

## Common mistakes

- **One index.** Each covers a different set of publishers and languages; combine them.
- **Documents without metadata.** A mention without a year and a type cannot be reported.
- **Name search only.** Reference search finds the papers that cite the DOI without naming the survey in the text.
- **No coverage measure.** A count without coverage reads as a total.

## Verification

- **Sources:** each listed source has a recorded method and terms.
- **Collection:** the scheduled run produces documents with complete metadata from both routes; duplicates across sources are merged.
- **Coverage:** the share of the reference list found, per source, reported with the latest run.
