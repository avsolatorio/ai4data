# 8. Reporting of use

**Question:** Can use be reported and interpreted?

## Rationale

A use report answers the questions management asks: which products are
used, by whom, for what, and whether that is changing. It also carries the
caveats without which the numbers mislead: which sources were covered, what
share of known uses the collection contained, and what the extractor's
recall was. Combined with access statistics (downloads and API calls,
counted the way the research data community counts them) and with a check
of how AI systems answer, it gives a rounded picture of use.

## Target state

- A report per period gives, for each dataset, the documents that mention and that use it, by year, document type, and source, with co-use.
- Access statistics are counted following the COUNTER Code of Practice for Research Data and reported next to the mentions.
- AI systems' answers are checked with a fixed question set on a schedule.
- Every report states its coverage and the extractor's recall.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | Publish a list of documents that cite each flagship dataset, updated each quarter. |
| **AI-ready** | Produce the use report from harmonized mentions and the documents table. Add COUNTER-aligned access statistics and the AI visibility check. State coverage and recall. |
| **AI-native** | Publish the report with the data, show "used in" on each dataset page from the results, and track trends across periods with a stable scope. |

:::info[Running example]
Across six documents, the household budget survey is used in two, the
labour force survey in one, the undernourishment indicator in one, and
the unemployment indicator in one; the food security report is mentioned
in two without being used. Two documents also use other
organizations' data alongside.
:::

<Recipe title="8.2 Add access statistics, citation counts, and the AI visibility check" level="AI-ready" skills="Web analyst; dissemination officer" time="One day to set up; two hours per period">

**Result:** downloads and API calls, identifier citations, mentions, and
a record of how AI assistants answer questions the data answer, side by
side per dataset.

1. Take the access counts of [chapter 2](./access.mdx) (regular and
   machine requests per dataset and month) and the citation counts of
   [chapter 3](./citations.mdx) (unique citing documents per dataset,
   with the sources that found them).
2. Run the AI visibility check from the
   [dissemination cookbook](/cookbook/ai-ready-dissemination/monitor-use):
   a fixed set of questions asked of two or three assistants each
   month, recording whether the organization is cited, whether the
   figure is right, and whether the link resolves.
3. Present the four measures side by side per dataset, each with its
   unit (requests, citing documents, documents with mentions, answers)
   and its caveat. They answer different questions and move
   differently.

**What this does not do.** Downloads count files, citations count
reference lists, mentions count documents, and the AI check samples
answers. None is a count of users or of decisions influenced, and the
report says so.

</Recipe>

<Recipe title="8.3 State coverage and recall with every count" level="Foundational" skills="Dissemination officer" time="Part of each report">

**Result:** every number in the report is read with the facts that
bound it: how much of the known literature the collection contains, and
how much of what is there the extractor finds.

1. Coverage: the share of the reference list of known uses that the
   collection contained, per source type ([chapter 4](./collect.mdx)).
2. Recall: the extractor's recall on the labelled sample, per document
   type and language ([chapter 6](./detect.mdx)).
3. Match rate: the share of mentions resolved to an identifier
   ([chapter 7](./harmonize.mdx)).
4. Print the three with the counts. When comparing periods, note any
   change in sources, model, or threshold.

**What this does not do.** Coverage and recall bound the counts from
below; they do not estimate the true total. An estimate of total use
needs a sampling design over sources, which is a larger exercise than
this guide covers.

</Recipe>

## Implementation options

- **Use report:** the script in this chapter from harmonized mentions; a dashboard once the pipeline runs on a schedule.
- **Access statistics:** COUNTER Code of Practice for Research Data; DataCite citation events for datasets with DOIs.
- **AI visibility:** the fixed question set and log from the dissemination cookbook.
- **Publication:** "used in" lists on dataset pages, as the Microdata Library's citations pages show.

## World Bank examples

- The [Microdata Library](https://microdata.worldbank.org/citations) publishes the citations of each study.
- [Monitoring of Data Use](/docs/data_use/) names impact measurement, gap analysis, evidence-base tracking, and catalog enrichment as the downstream uses of harmonized mentions.

- [Microdata Library citations](https://microdata.worldbank.org/citations): a published "used in" list per study, the form recipe 8.1's output takes on a dataset page.

## Common mistakes

- **A count without coverage.** It reads as a total and is an undercount of unknown size.
- **Mentions and downloads added together.** They count different things.
- **A rise after adding a source.** Growth or scope change; the report has to say which.
- **Reports nobody acts on.** Chapter 9 is the reason the report exists.

## Verification

- **Report:** produced per period from the harmonized mentions with the documents table; figures reproducible from the files.
- **Caveats:** coverage, recall, and match rate stated in the report.
- **Access statistics:** machine and regular access separated, following the Code of Practice.
